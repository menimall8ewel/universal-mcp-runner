# Skill 原则化改版与复审报告

- 审计基线：91edcf8e2c01906e0f2793a662375e1d0567343b（1.1.6）。
- 本次版本：1.2.0；正文、插件版本同步。
- 目标：降低规则自身维护成本，保留用户既定执行边界与全局可靠性目标。

## 改动结果

正文从 17,501 字符收敛至 6,973 字符，减少约 60.2%。仍只有一个规则正文；入口、市场目录和名称不变。

将重复的“最优、复用、稳定、低维护”集中到统一决策原则；按执行职责组织事实核验、配置、上游边界、工具、续办、恢复、验证和交付。去除正文中固定厂商方法清单、特定命令和具体工具案例，保留少量方法来源入口。先前 26 项来源及产品示例仍可从基线提交读取，未把它们移成新的必读配套正文。

检索改为按决策缺口、有界、可复用依据；保留主动吸收相关工程方法及成熟任务产品，不强制每次重新调查所有类别。具体版本、价格、平台定位、运行阈值与测试参数在任务中核实，避免每次产品变化都改 Skill。

## 补强点

1. 测试证据对应代码/制品、配置、依赖、环境、负载、时间及执行方式；复用时核对影响范围。相关条件改变补测，不凭“以前通过”放行，也不机械全量重测。
2. 明确在实际生效入口之前满足发布条件，包括提交或配置写入触发的自动发布，避免上线后补测或重复部署。
3. 产品与项目知识留在运行记录中，规则只因真实需求、冲突或可复现失败且用户明确要求才修改。

## 验证与复审

- YAML 解析、名称与目录对应、OpenHands 触发词结构、章节引用检查通过。
- 去除 OpenHands 扩展 triggers 字段的临时通用投影通过 quick_validate；不声称原文件通过不支持该扩展的通用校验器。
- 冻结条款和直接执行段落与基线逐字一致。
- 对上述关键边界作静态语义走查，未发现明显悬空引用或直接冲突；这不是独立 Agent 行为测试。
- 行为用例从 10 个扩充到 17 个，针对当前 1.2.0。新增上游边界、全局组合、旧证据失效、组合故障禁止上线、自动发布入口、简单任务和有效证据复用。
- 所有 17 个用例均为 not_run：当前工具目录没有可调用的 OpenHands 执行器，未执行真实 Agent 回归、生产稳定性或故障注入测试。不能宣称决策准确率或线上可靠性已经提升。
- 未安装测试平台，未修改业务程序或平台发布设置；本次没有将文字条件转换成平台强制门禁。实际项目执行时应复用其已有检查入口。
- 本次只是 Skill 与验收资料变更；仓库 README 描述主分支关联自动部署，平台实际是否触发及生产状态未核实，不能将 Git 提交成功说成生产验证成功。

## 结论

原则化正文可以减少因产品更替而反复修改规则的需求。当前完成静态改版与复审，运行验收尚未完成。使用时仍需加载目标正文并核实当时的事实；长期稳定使用不等于永久免维护。
